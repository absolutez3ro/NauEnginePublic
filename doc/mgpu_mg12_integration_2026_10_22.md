# MG-12: тестовая интеграционная ветка, 22.10.2026

Ветка `mgpu/MG-12-integration-test` объединяет готовые ветки команд для совместной проверки. Это подготовка к MG-12, а не отметка о закрытии MG-12: экранного примера с переключением 1 GPU / 2 GPU пока нет.

MG-06 уже является предком MG-10, MG-09 — предком MG-08. Для MG-04 выполнено отдельное слияние истории: его итоговый заголовок совпадал с включённым в MG-08. Авторы и исходные коммиты сохранены; история не переписывалась. Конфликты слияния были только в CMake-списках тестов; оставлены проверки всех компонентов и оба варианта аллокатора.

Отдельной ветки MG-07 в origin нет. DIRECT queue/list/allocators/fence есть у прохода MG-10, COPY queues — у MG-08. Общая подсистема очередей с отдельной COMPUTE queue для вторичного устройства этим слиянием не добавлена. Поэтому фразу «MG-07 полностью закрыта» следует согласовать с владельцем задачи; для текущего fullscreen draw и передачи имеющихся очередей достаточно.

`sm_team/mgpu_features_transfer` не включена: это отдельный перенос инфраструктуры/теневого примера, не зависимость проверяемой связки MG-06–MG-13. Реализация AO по материалам Богданова — следующая работа команды, не часть этого слияния.

## Что проверяет новый сквозной тест

`MultiGpuIntegration.AnimatedFullscreenPassArrivesOnOtherAdapter`:

1. Создаёт два устройства: пару физических адаптеров, если она есть, иначе аппаратный адаптер + WARP. На этой машине использованы RTX 4060 Ti и WARP.
2. Создаёт `DeviceFullscreenPass` на устройстве-источнике: VS/PS, PSO, root signature, буфер констант и render target.
3. Меняет цвет каждый кадр и выполняет настоящий shader draw.
4. Передаёт render target через `CrossAdapterChannel` MG-08 и shared fence MG-09.
5. Ставит `sourceReleased` в очередь прохода через `waitForExternalWork()`: исходная текстура не перезаписывается, пока COPY queue читает предыдущий кадр.
6. На принимающем устройстве COPY queue ждёт полученный fence, затем читает локальную текстуру в readback. Проверяется каждый пиксель.
7. Выполняет по шесть кадров при 1920×1080 и 961×541 в обе стороны. Нечётная ширина проверяет row pitch, повторные кадры — переиспользование двух слотов.
8. Проверяет ошибки debug layer и возврат всех выделений в аллокаторы.

Ожидание между устройствами выполняется очередями GPU. CPU ждёт при проверочном readback каждого кадра; этот тест подтверждает корректность, но не производительность и не отсутствие CPU-ожиданий в будущем игровом цикле.

В standalone-сборке используется тестовый allocator. В полной статической сборке с `NAU_MGPU_ENGINE_TESTS=ON` тот же тест использует настоящий `NauDeviceResourceAllocator` и `ResourceMemoryHeapProvider`, то есть `CreatePlacedResource` и пулы Nau для локальных ресурсов обоих устройств. Общая межадаптерная память по-прежнему создаётся каналом MG-08 отдельно: её должны открыть оба устройства.

Остальные проверки передачи и fence также принимают аппаратный GPU + WARP. Отдельные тесты наличия двух физических GPU и удаления физического сигнализирующего устройства сохранены как дополнительные. WARP достаточен для согласованной функциональной проверки; результаты WARP не являются замером ускорения двух физических видеокарт.

Тест использует низкоуровневый `CrossAdapterChannel`. Обёртки `d3d::mgpu` с `BaseTexture`/`Sbuffer` входят в полную сборку, но этот тест не заменяет их проверку в render graph.

## Результаты

Среда: Windows x64, Visual Studio 18 / MSVC 19.51, Windows SDK 10.0.26100, RTX 4060 Ti + WARP; установленный Python 3.9 / Cymbal и DXC. Полная сборка статическая, Release; standalone — Debug.

- Полный CTest с пулом Nau: **75 passed, 3 skipped, 0 failed** из 78 тестов, 64,05 с. Сквозной draw → transfer → readback прошёл.
- Standalone CTest: **71 passed, 3 skipped, 0 failed** из 74 тестов, 33,12 с.
- В сквозном тесте с пулом Nau разрешено только диагностическое предупреждение D3D12 **#1318 `WRITE_COMBINE_PERFORMANCE_WARNING`**, возникающее при создании штатных upload heaps. Оно не относится к корректности передачи. Все остальные WARNING и все ERROR/CORRUPTION остаются причиной провала теста; глобальные фильтры debug layer не менялись.
- При сортировке include выявлена скрытая зависимость `genericSbufferImplementation.h` от предварительного подключения `tql.h`; добавлен прямой include. Render и engine-тесты повторно собраны с этим исправлением.
- `clang-format --dry-run --Werror` для всех добавленных C++-файлов и `git diff --check` прошли.

Render, Graphics (включая исходники MG-13), `test_multi_gpu`, `test_multi_gpu_status` и `SceneBaseSample` собраны в Release x64. Кэши шейдеров sample сгенерированы.

Четыре запуска SceneBaseSample работали по 30 секунд, затем закрывались через обычный запрос закрытия окна: во всех случаях **exit code 0**, без принудительного завершения. Проверялся запуск/рендер-цикл по логам и CSV; визуальная сверка окна и экранная запись не выполнялись.

| Запуск | Что подтверждено | CSV |
|---|---|---|
| `multiGpu=false`, profiler включён | Основной render graph на GPU 0, штатное завершение | 5217 кадров, 93906 строк, `gpu=0`, `mode=1gpu` |
| `multiGpu=true`, второго аппаратного адаптера нет | MG-11 сообщил `no suitable secondary GPU`, сцена продолжила работу на GPU 0 | 4812 кадров, 86616 строк, `gpu=0`, `mode=2gpu` |
| `SELFTEST=1` при `multiGpu=false` | Отдельное устройство WARP, копия 64 MiB на GPU 1, проходы сцены на GPU 0 | 801 кадр, 15156 строк; `copy_test` на `gpu=1` |
| `SELFTEST=2` при `multiGpu=false` | Копия 64 MiB на WARP и передача 32 MiB WARP → RTX 4060 Ti | 395 кадров, 2053 строки; `src`, `dst`, `sum`, `span` |

В `SELFTEST=2` зарегистрированы частоты GPU 0 = 1 000 000 000 Hz, GPU 1 = 10 000 000 Hz. После первых 30 кадров получено 368 измерений передачи: медиана `src` 22,787 ms, `dst` 10,205 ms, `sum` 32,820 ms, `span` 33,512 ms. Это диагностические значения WARP для тестового копирования, не оценка ускорения сцены. Все прочитанные значения CSV конечны и неотрицательны. Скрипт сравнения CSV успешно сформировал таблицу baseline/fallback; её разницу нельзя трактовать как ускорение от двух GPU, поскольку оба запуска исполняют сцену на GPU 0 и условия прогонов не нормализовались.

У self-test метка `mode=1gpu` соответствует конфигурации `multiGpu=false`, хотя сам тест явно создаёт WARP. При fallback метка `mode=2gpu` сохраняется при реально работающем только GPU 0. Это подтверждает, что поле отражает запрошенную конфигурацию, а не фактическое число работающих устройств.

Во всех четырёх запусках при завершении зарегистрирована ошибка сохранения `cache/dx12.cache`: `Failed to open ... to serialize pipeline cache`. Она не сорвала закрытие и получение CSV; состояние кэша требуется разобрать отдельно. Runtime D3D12 debug layer в этих Release-запусках выключен; проверки debug layer выполнялись отдельными CTest выше.

Локальные доказательства находятся в `build/test-engine-final.log`, `build/test-standalone-final.log`, `build/engine-results.xml`, `build/standalone-results.xml`, `build/runtime/*.result.json`, `build/runtime/*.csv`, `build/runtime/*.stdout.log`, `build/runtime/summary.json`. Сырые логи и CSV не включены в Git. Опубликованный отчёт фиксирует результаты на `36caab7c` и последующую правку только пробелов в `graphics_impl.cpp`.

## Проверка стиля и существующих PR

Просмотрены исходные PR #2–#7, их описания и inline-комментарии; на момент проверки inline-комментариев не было. Исходные PR не закрывались и их описания не перезаписывались.

Для новых файлов MGPU применён репозиторный clang-format: Allman, четыре пробела, расположение указателей и обязательные фигурные скобки. В новых заголовках добавлены имена файлов/уведомления об авторских правах. В тестах передачи и fence заменены STL-контейнеры на EASTL с malloc-аллокатором, чтобы сохранить standalone-сборку без NauKernel; убраны blanket `using namespace`, имена вспомогательных функций приведены к camelCase. В реализации канала убрано общее `using namespace` и неподтверждённое обобщение о скорости размещения shared heap.

Это не заявление о полном соответствии всего унаследованного кода руководству. Публичные имена согласованного контракта `d3d::mgpu` остаются в snake_case; в старых добавлениях MG-06/08/09/11 и MG-13 остаются отличия именования членов/enum/констант и места с `auto`. Их лучше исправлять согласованно с авторами API, отдельным изменением. Старые большие файлы драйвера целиком не переформатировались.

Описание PR #7 относится к его собственной базе `main`: утверждение, что `dx12.multiGpu` читает только профайлер, не относится к этой объединённой ветке — здесь его читает и MG-06/11. При этом включённый флаг ещё не означает, что второй GPU действительно рендерит сцену. Поле `mode` в CSV отражает запрошенную конфигурацию.

## Что оставалось перед закрытием MG-12 на 22 октября

Продолжение с подключением экранного примера и актуальными результатами находится в [отчёте от 23 октября](mgpu_mg12_sample_2026_10_23.md). Список ниже фиксирует состояние предыдущей проверки.

- Подключить проход к sample/render graph: анимированная картинка на GPU 1 → канал MG-08/09 → локальная текстура GPU 0 → показ в окне.
- Добавить управление режимом 1 GPU / 2 GPU и работающий путь той же картинки на одном GPU. Флаг устройства и отдельный GPU draw сами по себе не обеспечивают переключение техники.
- На месте ошибки передачи связать результат с MG-11 (`report_secondary_gpu_failure`) и переключением техники. Нулевой ticket может означать нормальный пропуск кадра из-за заполнения очереди, поэтому нельзя считать любой нулевой ticket поломкой GPU.
- Добавить обработку завершения/потери устройства для всей цепочки и проверить её. В MG-08 `CrossAdapterChannel::reset()` ждёт с `INFINITE`, а в self-test MG-13 `waitIdle()` использует блокирующий `SetEventOnCompletion(..., nullptr)`. Если queued dependency никогда не сигнализируется, эти пути могут зависнуть. Безопасный deferred-retirement деструктор MG-10 не исправляет соседние компоненты автоматически. Простая замена ожидания тайм-аутом с освобождением ресурсов небезопасна.
- Регулярно вызывать `DeviceFullscreenPass::collectRetiredResources()` в потоке рендера, в том числе при shutdown; не крутить бесконечный цикл до нулевого результата.
- Подключить MG-13 к реальным очередям прохода и канала. Текущий self-test использует собственные очереди и копии; `SELFTEST=2` временно заменяет источник измерений GPU 0 и не измеряет проходы движка. Источник D3D12 timestamps пока принимает DIRECT/COMPUTE, тогда как MG-08 использует COPY: измерения COPY queue требуют отдельной поддержки.
- Записать экранный результат/видео и сравнивать 1 GPU / 2 GPU на одинаковом workload. Слияние и функциональные WARP-тесты не доказывают ускорение.

После этих шагов — подключение входов depth/normals и алгоритма AO. Для AO раннему depth prepass пока не хватает normals: в существующем графе они появляются после `fill_gbuffer`.

## Повторить проверки

```powershell
git submodule update --init --recursive
cmake -S engine/core/modules/render/tests/test_multi_gpu -B build/multi_gpu_tests -G "Visual Studio 18 2026" -A x64
cmake --build build/multi_gpu_tests --config Debug --parallel 2
ctest --test-dir build/multi_gpu_tests -C Debug --output-on-failure
```

Для установленного VS 2022 заменить генератор на `Visual Studio 17 2022`. Для полной сборки: `BUILD_SHARED_LIBS=OFF`, `NAU_CORE_TOOLS=OFF`, `NAU_CORE_SAMPLES=ON`, `NAU_CORE_TESTS=OFF`, `NAU_FORCE_ENABLE_SHADER_COMPILER_TOOL=ON`, `NAU_MGPU_ENGINE_TESTS=ON`, доступные Python/Cymbal и DXC. Собрать `test_multi_gpu`, `test_multi_gpu_status`, `SceneBaseSample`; выполнить CTest с фильтром `MultiGpu|DeviceResource|DeviceFullscreenPass`.

MG-13 включается через `NAU_GPU_PROFILER=1`; `NAU_GPU_PROFILER_CSV` задаёт файл. `NAU_GPU_PROFILER_SELFTEST=1` проверяет копию на втором устройстве, `=2` — ещё и передачу между устройствами. Без этих переменных self-test выключен. Скрипт `tools/scripts/compare_gpu_timings.py` сравнивает CSV; не использовать `--real-2gpu` как доказательство реального ускорения.
