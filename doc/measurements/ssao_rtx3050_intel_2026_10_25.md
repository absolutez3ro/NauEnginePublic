# SSAO on RTX 3050 Laptop and Intel Graphics

The supplied Windows logs identify GPU 0 as NVIDIA GeForce RTX 3050 6GB Laptop GPU and GPU 1 as Intel(R) Graphics, PCI ID `8086:A7AB`. Both are hardware adapters. The four runs used lit SSAO, profiling on, captures/reference rendering off, and vsync/adaptive vsync off. Each run resized from the initial 634x611 window to 1920x1009. Half-resolution AO is 960x504; full-resolution AO is 1920x1009.

The original CSV, result JSON and stdout filenames and SHA-256 hashes are recorded with the [machine-readable results](ssao_rtx3050_intel_2026_10_25.json). Raw files remain outside the source tree. The supplied files do not record the source revision, executable hash, camera movement or repeated-trial conditions. These results demonstrate hardware execution and provide exploratory GPU timings. They do not identify the exact binary as the current PR revision or establish end-to-end speedup.

## Method

Use `tools/scripts/summarize_ssao_timings.py` with `--warmup-frames 500`. It validates finite/nonnegative timings, duplicate keys, transfer directions and `sum = src + dst` within CSV rounding. Transfer integrity includes warmup; timing statistics exclude it. Median and P95 use the same method as the script. No FPS is derived from GPU timestamps.

Both secondary runs later switch to primary execution: the full-resolution log reports the final change at SSAO frame 5244, the half-resolution log at 5032. The CSV mode stays `2gpu`. To avoid mixing paths, classify each GPU 0 `Frame` using scopes in the same profiler frame:

- `primary`: `ssao_raw` on GPU 0, without `ssao_reuse`.
- `secondary`: `ssao_reuse`, without `ssao_raw` on GPU 0. This includes both newly received and cached secondary maps.
- `mixed`: both markers, possible with reference captures. `unclassified`: neither marker. Neither occurs in these post-warmup samples.

SSAO frame counters and profiler frame IDs are separate counters. They are not joined by assuming an offset. All comparisons below use recorded profiler scopes.

The four GPU 1 pass means sum to 14.8663 ms at full resolution and 3.5092 ms at half resolution. These sums describe pass work, not complete job latency. COPY `/sum` is source plus destination GPU work. Calibrated `/span` also includes scheduling between those timestamps; it excludes waiting before the source timestamp. Do not sum overlapping queue intervals into frame time.

Validation found 1,738 complete transfer pairs in the full-resolution CSV and 4,588 in the half-resolution CSV. No normal map is transported: GPU 1 reconstructs normals from depth. With depth-only R32F input and R8 AO output, logical payload per submitted job is 9,686,400 bytes full or 2,419,200 bytes half, before row alignment and local copies.

Every run satisfies `secondary + primary + reused = frames`. All four stdout logs contain the final SSAO counters and `Graphics shutdown completed`. Their JSON files record `forcedTermination=false` but `exitCode=null`; zero process exit codes are not established by these materials. New runner outputs retain the process handle, reject an unreadable exit status, and record checkout revision, dirty state and executable SHA-256. The checkout revision alone is not proof that an executable was built from it.

All four logs contain the known `cache/dx12.cache` save error. The primary-overlap and secondary-full logs also report a 500 ms low-latency waitable-object timeout. The runs contain no pixel/reference captures or PIX/GPUView queue trace. They do not validate temporal image quality, useful simultaneous queue occupancy, or the latest source-depth-history fix on this hardware.
